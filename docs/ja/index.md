# ithyno

> **仕様書と進捗管理の壁をなくす。**
> AI が仕様に沿って自律的にタスクを進め、人間は直感的なダッシュボードで開発をコントロール。
> 人間と AI のコラボレーションによる、新しいソフトウェア開発の形。

**ithyno** は、[OpenSpec](https://github.com/Fission-AI/OpenSpec) の仕様定義を唯一の真実のソースとし、AI エージェントへの指示（提案・実装・レビュー・検証）を行うコマンド（Skill）を実行しながら、その進捗を視覚的に管理できるローカルダッシュボードです。

- **新たな状態管理用データベースは不要**: 進捗は `tasks.md` 内の `- [ ]` から `- [x]` への変更として記録され、UI はそれを可視化・編集するだけです。任意のテキストエディタで直接タスクをチェックできます。
- **人間と AI の共存**: エージェントはプレーンな Markdown を処理し、人間はカンバンや進捗ツリーを見ながら全体の状況を視覚的に把握・制御します。
- **Git が監査ログ**: 「誰がいつ、どのタスクを完了したか」は、通常の Markdown コミットの差分として Git に正確に記録されます。（TODO: 各タスクの Agent への割り振り、Co-Authored コミットとの連携）

## 誰のためのツールか？

- **バイブコーダーから仕様駆動（Spec-Driven）開発にステップアップしてみたい方**: プロンプトだけで「なんとなく（Vibe）」コードを書く状態から脱却し、仕様化されたタスク（`tasks.md`）ベースで AI を的確にコントロール・管理する手法を身につけたい開発者。
- **並行エージェントによる開発スキルを求めている方**: Git Worktree 隔離を用いて複数の変更案を並行して AI エージェントに解決させる高度な並行エージェントワークフロー（Parallel Agent Workflows）を実践・習得したい開発者。
- **複数のエージェントを組み合わせて最適な連携（ベストプラクティス）を探りたい方**: Code / Review / Verify など、役割の異なる複数のエージェント（Copilot CLI や Claude Code 等）を組み合わせ、自プロジェクトに最適なエージェント協調・運用フローを模索したい方。
- **エージェントの役割（Code / Review / Verify）を明確に指定したフローを運用したい方**: AI に単にコードを書かせるだけでなく、コーダー、レビュアー、検証者といった役割（ロール）ごとの権限・責任境界を持たせた、より安全で確実な自律開発プロセスを構築したい方。
- **仕様駆動開発（SDD）を実践する開発者・チーム**: 重厚なタスク管理データベースの代わりに、Markdown 仕様書を唯一の真実のソース（Single Source of Truth）とし、Git 履歴を確実な監査ログとして運用したいチーム。
- **技術リーダー / マネージャー**: どの仕様が変更されつつあるのか、現在何が進行中か、エージェントがどこで止まっているのかをクリアに視覚化し、進捗管理を行いたいリーダー。

## 主要コンセプト

- **仕様駆動開発（SDD）と OpenSpec**: すべての開発作業は `openspec/` ディレクトリ配下の仕様ファイルに基づいて駆動されます。仕様の変更提案がそのまま開発ライフサイクルを進めます。
- **Git Worktree による並行実行**: 各変更提案は、隔離された個別の Git Worktree（`.worktrees/<change-id>/`）へ自動でチェックアウトされます。これにより、複数の AI エージェントや人間がファイルの競合を気にせず並行してコード作成・テスト・コミットを実行できます。
- **カンバンボード**: 提案された変更（Proposed）、実装中（Coded）、レビュー中（Reviewed）、完了（Done）のステータスを一覧し、埋め込み PTY ターミナルを通じて進捗状況をリアルタイムに監視できます。
