# Secrets

**Secrets** では、プロジェクトのdotenv互換 `.env*` プロファイルに保存する
開発用変数を管理できます。ダッシュボード上部の **Secrets** から開きます。

## プロファイルを選択する

ithynoはプロジェクト直下の `.env` と `.env.<profile>` を検出します。新しく
起動するManagerターミナルとWorkerで使用するプロファイルを選択してください。
プロファイルがない場合は、同じ画面から最初のプロファイルを作成できます。

変更は新しく起動したプロセスへ反映されます。起動済みのManagerへ新しい
プロファイルや値を反映するには、ターミナルの更新ボタンから再起動します。

## 値を安全に管理する

値はRevealするまでマスクされます。各行のアイコンから、表示・非表示、コピー、
編集、削除を実行できます。編集と削除はすぐには保存されず、内容を確認してから
プロファイルへ反映します。

実値を含む `.env*` はバージョン管理から除外してください。Gitへ追加する場合は、
プレースホルダーだけを含むサンプルファイルを使用します。

## プロファイルを暗号化する

Active profileの横にある **Encrypt profile** を選択します。ithynoは同梱した
dotenvxを使用し、プロジェクト直下の `.env.keys` を作成または更新します。
確認画面には対象プロファイルが表示され、既存のルールを書き換えずに
`.env.keys` が `.gitignore` へ追加されます。

`.env.keys` には復号用の秘密鍵が含まれます。Gitへコミットしたり公開したり
しないでください。暗号化した `.env*` をコミットするかどうかは、プロジェクトの
セキュリティ方針に従ってください。

dotenvx Nativeを利用できる場合は、次の操作も表示されます。

- **Move key to OS storage** — OSの安全なストレージへ鍵を保存し、そのプロファイルの
  鍵を `.env.keys` から削除します。
- **Copy key to OS storage** — OS側にも鍵を保存し、`.env.keys` は残します。

これらは任意の機能です。通常のローカル開発では `.env.keys` をそのまま利用できます。

## プロファイルを削除する

Active profileの横にあるゴミ箱アイコンを押し、表示されたファイルパスを確認します。
削除されるのは対象の `.env*` ファイルだけです。`.env.keys` またはOSストレージに
ある秘密鍵は、別途明示的に削除するまで残ります。

## CIとAgentプロセス

CIでは、CIプラットフォームのSecret設定から `DOTENV_PRIVATE_KEY`、または
`DOTENV_PRIVATE_KEY_DEVELOPMENT` のようなプロファイル固有の鍵を渡します。

ithynoはManagerまたはWorkerの起動前に選択済みプロファイルを解決します。
プロセスには解決済みのアプリケーション変数だけが渡され、dotenvxの秘密鍵自体は
渡されません。
